# 双16键键盘扩展（2026-10-19）

工程入口：`D:\gaoyun\piano_v2_audio_fix\yinyue_fashengqi.gprj`。

本轮将同一个主工程扩展为两块TTP229式16键模块，共32个不同的MIDI音高。综合、仿真和时序最终结果在本页末尾与 `audit/keyboard32_20261019/FINAL_ACCEPTANCE.json` 中记录；未记录最终PASS前，不以历史FS或旧时序报告作为本轮通过证明。不自动烧录。

## 音域及显示

默认保留原模块音高：模块1逻辑键0～15 → MIDI60～75（C4～D♯5），模块2逻辑键0～15 → MIDI76～91（E5～G6）。全局键号0～31，不截断成四位，不重复音高。

`KEY_BASE_NOTE`、`KEY_NOTE_TABLE` 继续配置原模块；新增 `KEY2_BASE_NOTE` 默认等于 `KEY_BASE_NOTE+16`，也可单独用 `KEY2_NOTE_TABLE` 配置。两模块的原始位序可分别用 `KEY_RAW_*`、`KEY2_RAW_*` 调整。跨两块模块的重复MIDI表被拒绝。实体从左到右的位序必须用实际模块确认，不根据模块外观猜测排列。

此前音源测量相对推荐48～79，本次按“原来基础上增加”保留60～75；这不改变此前对80～91响度与音质的保留意见。若以后选择48～79，只需将 `KEY_BASE_NOTE` 设为48，再重新仿真/实现；当前构建具体默认值以最终验收记录为准。本轮是实体输入及复音功能验证，不宣称完成32个优质音色的听评。

按此前要求，屏幕的16个琴键位置及音名仍对应第一块模块，未把两个模块折叠到同一组灯位。Voice计数、波形、FFT和李萨如来自实际总音频，包含第二块模块。

| 原模块 | SCL | C21 / Bank5 | J26第11脚，PMOD2_IO0 | ttp229_scl |

两模块共地，各自使用独立SCL/SDO；不连接两个SDO输出。新增SDO启用上拉，未插模块且输入保持高电平时报告全松开。原16键、DAC、HDMI、时钟与复位的外部引脚位置不变。

两模块均需硬件设置为16键、多键同时触发、低有效串行模式；具体跳线以模块型号说明为准。默认两个PROFILE均为1，关闭旧的8键镜像猜测屏蔽，避免第一次按住FFFF和弦时丢弃上8键。保留PROFILE0作为诊断选择；它不能证明实际模块具有16键多键能力。

## 实现及验证边界

- `src/keyboard/ttp229_keyboard_pair.sv`：两个独立Reader、两帧确认、各自完整帧接纳与位序映射；单模块错误不阻塞另一模块。
- `src/ttp229_event_bridge.v`：默认16键兼容，主工程显式选择32键、5位全局键号；共用原FIFO，保持Note Off优先、背压期间字段稳定。
- 板级顶层：拼接32位状态送入同一个事件桥与原32 Voice音源；实际FIFO接纳状态扩展到32位。GAO同步覆盖两模块。
- 当前GPRJ启用新增RTL，CST显式分配新增两根管脚，禁止工具自行选择新IO。
- 保留钢琴参数/Loader/Voice/增益/FX、FFT、HDMI、双DAC及已验证视频时钟/SDC。没有加入其他乐器音源。

仿真包括：32键逐位串行模型、首次全32键和弦、跨模块独立释放、16深度FIFO满背压、快速变化/复位、无效映射及模块故障隔离；真实32个钢琴Voice同时运行、逐路有非零样本、双DAC解码比对及真实FFT/TMDS/状态链路；原16键PCM及双DAC管脚与修改前RTL对照。

串行模型按TTP229-BSF式协议，功能仿真的PLL/物理视频串行器使用边界替身；实际器件映射与时序由Gowin实现验证。上述不等于实物协议/线序/模拟音质验证。旧8键/单键模块配置不会被软件扩展成32键复音。
