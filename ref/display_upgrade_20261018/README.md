# 显示升级版：原风格 / 1080p30

本目录保留原来的**绿色波形、青色X/Y轨迹、彩色频谱、点阵文字**，没有使用上一轮的新UI风格。

## 改了什么

- 输出改为 **1920×1080、30Hz逐行扫描**；像素时钟74.25MHz，串行时钟371.25MHz。
- X/Y取样由8位提高到16位，弱信号不再过早被截成中心几个点。
- 两路真实声部输入使用同一采样时刻；只有混音一路时，使用显示专用Hilbert正交分析，不再固定延迟32点。
- X/Y改为正方形坐标，去掉直流偏置，两轴共用一个自动缩放，保留真实幅度比例。
- 点轨迹增加连线；没有新快照时保留上一帧。静音/直流显示“无信号”，不放大成假图形。

**这些处理只改变画面，不改变声音、音量、DAC或音频PLL。** 多音色、谐波丰富的钢琴本来就可能呈复杂轨迹，不会被强行画成标准圆。

## 先看哪里

- `src/`：升级后的显示源码。
- `visual_demo.gprj`：独立显示测试工程，顶层`visual_test_top`，内置实时1kHz测试信号，**不是完整电子琴工程，不输出DAC声音**。
- `src/visual_display_top.sv`：未来接入钢琴用的显示封装，输入最终PCM和可选两路声部。
- `constraints/`：测试工程引脚及1080p30时序；合并模板不能覆盖原工程约束。
- `sim_out_visual/display_1080p30.png`：实际RTL绘图导出的画面；不是实物照片。已生成，输入为测试数据。
- `sim_out_visual/verification_report.md`：本轮检查结果。

## 怎么检查

```powershell
Set-Location 'E:\xianshi(shengjiban)'
D:\anaconda\python.exe -B scripts/run_checks.py
```

本轮12组独立检查全部通过。脚本只生成本目录内的测试结果，不连接或烧录FPGA。覆盖高音、弱信号、幅度比例、静音、直流、取样配对、CDC/复位、FFT、视频时序和TMDS。

## 接入时注意

1. **E:\xianshi里没有源码，只有旧仿真产物。** 用户确认照片对应源码可能不在U盘；本版以`E:\xiugai\srctianjia`为基线。因此照片里的PIANO/NOTE/RAW等调试文字不在这份基线，不能承诺完全复现它们。
2. 如果原主工程已实例化`audio_visualizer`和`visual_video_clock`，保留其顶层连接，换入本版相关显示文件，并新增`visual_xy_source.sv`、`visual_xy_plot.sv`和`visual_ref_pll_mod.v`。不要只替换raster而保留旧PLL。
3. 最终PCM和pcm_valid接实际DAC锁存边界；X/Y必须是完整24位有符号声部样本且同拍有效。只有一路或无法保证双路有效时，xy_enable置0。
4. 视频引脚继续使用J11。两级视频PLL独立于原音频PLL；视频掉锁只复位显示分析。已有PLL_INIT只保留一份，不重复定义。
5. 合并后仍需Gowin重新综合、布局布线、核对时钟约束，并实测显示器能否接受1080p30。**本轮没有生成或烧录已验证的.fs。**

字体和原仪表布局按640×360逻辑网格进行整数3倍绘制，输出扫描确为1920×1080；没有用全屏图像缓存。30Hz是视频扫描刷新率，不等于每个分析模块每秒产生30份新数据；默认2048点FFT仍保留23.4375Hz频率格点，其数据更新率受采样窗和运算时间限制。

原`E:\xianshi`、`E:\xiugai`、钢琴工程及本地工程保持不变。详细接口与边界见`INTEGRATION.md`。

## 本轮中文显示

中文字形已直接放进 `src/visual_labels.sv`，不依赖电脑字体、外部字库文件或全屏缓存；使用12×12单色字形，再随原逻辑网格放大3倍。文字位置已避开轨迹与频谱区域。

当前显示接口没有音色、音符和发声数输入，因此本轮不虚构“钢琴 / 发声数 / 音符 / MIDI”演奏数据；接入实际钢琴工程时再由真实状态驱动。
