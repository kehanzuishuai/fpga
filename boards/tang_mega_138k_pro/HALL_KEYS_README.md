# 磁轴/Hall读数到按键动作（独立离线层）

默认16键，支持1～32键。本轮完成校准/滤波和按下/松开/力度识别，尚未加入Gowin GPRJ或板级top；没有修改GPIO、PLL、音频核心或DAC。它们不自行读取ADC引脚、不生成MIDI音符，也不代表实物手感已验证。

数据流：`原始12bit读数+键号+采集时间 → hall_position_filter → 0～4095行程 → hall_key_events → 键号/按下松开/力度/时间`。

后续才将`hall_scan_store`更新的数据串行送进来、把键号映射为音符并接入note_event_fifo。不能把16路updated直接当成一个valid而不保存其余数据，否则可能漏键。本轮不实现这个桥接。

## 校准、滤波和行程

`hall_position_filter.sv`提供：

- `cfg_valid/cfg_ready`配置`cfg_key`的`cfg_rest/cfg_down`，分别为松开/到底的12bit读数；每键独立，兼容正反方向。差值小于`MIN_SPAN=64`时校准无效。提供保存/配置接口，不自动猜端点、不掉电保存；复位后需重新配置。
- 配置优先于新采样，但不打断正在换算的样本。每次配置都输出一条该键`position_good=0`记录，时间取`cfg_timestamp`，以释放已按住的键并重新等待松开，即使新校准有效也如此。
- `sample_valid/sample_ready`接收`sample_key/raw/good/timestamp`。时间必须是采集时刻的系统时钟计数，不是处理完成时间。`sample_good=0`清空该键滤波历史并传递无效记录，不清除校准值。
- 原始值以Q4保存：`f_next=f+floor((raw*16-f)/2^FILTER_SHIFT)`，先取`floor(f/16)`再做行程换算。SHIFT=0直通，1～4渐强，默认2。首次有效样本直接初始化，不从零爬升。
- 根据校准方向，将距离夹紧到0～span，再算`floor(distance*4095/span)`；0表示松开，4095表示到底。采用一套共享24步恢复除法/13bit比较减法，乘4095采用移位减法；每键校准和滤波状态仍独立。
- `position_valid/position_ready`输出。无反压时，从输入接受到输出valid被观察到为1个系统时钟（端点/配置/无效）或25个时钟（普通换算），50MHz下0.02～0.5µs。这不包括ADC扫描、滤波、按键确认或发声延迟。

## 按键和速度力度

`hall_key_events.sv`每键独立保存准备、按住、移动起点、确认计数、候选力度与慢速标志。

| 参数 | 默认值 | 通俗解释 |
|---|---|---|
| START_POSITION | 256 | 超过这里开始计按压时间 |
| OFF_POSITION | 512 | 回到这里以下才算松开 |
| ON_POSITION | 2048 | 超过这里才算按下 |
| CONFIRM_SAMPLES | 2 | 连续两次该键读数满足条件才确认，可设1～16 |
| VELOCITY_STEP_CYCLES | 50000 | 时间基准，50MHz下1ms |

复位、校准或无效数据后，先看到一次行程<=OFF才允许触发，避免上电按住自动发声。按住时只检查松开阈值，松开时只检查按下阈值；阈值分开称“滞回”。短暂越过阈值但未满足连续确认次数，不产生动作。

力度使用首次超过START到本次连续ON候选第一个样本的时间，后续确认不改变候选力度。时间<=1/2/4/8/16/32/64/128倍STEP输出127/112/96/80/64/48/32/16，超过128倍为1；直接跳到ON时按127处理，因为采样没有更精确的速度信息。这是9档速度近似，不是压力测量或已调好的连续手感曲线，需实物调参。

32bit时间用无符号模减，可跨一次计数器回绕（50MHz下85.9秒一圈）。慢速移动持续更新时锁定最低力度，避免后来回绕误判快速。有效采样不能间隔一整圈仍标good；后续采集适配层应把过期/错误明确作为无效记录送入。

`event_valid/event_ready`输出`event_key/on/velocity/timestamp`，按下力度1～127，松开0。阻塞时保持待发动作并反压输入；无效数据/重校准对已按住的键发送一次松开，未按住不额外发送。复位直接丢弃待发动作并清空状态；未来接入合成器须协调复位/全部音符关闭，不能只复位本模块而让声音继续。

两级生产者都必须在ready=0时保持valid和数据。这里没有无限缓存，未来ADC桥接需保存并排队多键更新。KEY_W/COUNT_W是内部派生宽度，保持默认值。

## 自检和边界

```powershell
./scripts/run_checks.ps1 -Suite keys
```

脚本`verify_hall_keys.py`的Python参考采用有符号仿射映射/整数除法，RTL采用逐位恢复除法；逐条比对行程、good、键号、时间、动作、力度和最终按住位图。覆盖正反校准、最小span、两端、滤波、阈值抖动、全键、速度分档/回绕、无效/重校准、反压、换算中复位、事件阻塞时复位、随机输入和非法参数；严格Verilator和Yosys检查不屏蔽warning。原始结果位于被忽略的`sim_out_keys/`。

统一完整回归现在包含六suite（工具、ADC、Hall解释、音频、显示、双DAC），本轮已全部PASS，见[验证报告](verification/hall_keys_20261009.md)及[数据/源码哈希](verification/hall_keys_20261009.json)。历史五suite报告仅证明当时源码。实物回来后仍需校准端点、测噪声、调整滤波/阈值/力度手感，检查更新率和端到端发声延迟，不能仅凭仿真承诺≤5ms。
