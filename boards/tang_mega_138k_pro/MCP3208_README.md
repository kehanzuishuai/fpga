# 双MCP3208：16键原始采集（未接板）

本轮只完成采集和数据管理：两个ADC同时读取同一个通道编号，按0～7循环，共16个键。没有校准、滤波、按下判断、力度计算、音符事件或LED控制。新模块尚未加入板级top/GPRJ，也没有分配GPIO或修改时钟/管脚。

## 三个模块

- [mcp3208_dual_reader.sv](src/mcp3208_dual_reader.sv)：共享SCLK、DIN和CS，分别读取两根DOUT。请求通过`request_valid && request_ready`接收；结果通过`result_valid && result_ready`交付。结果无人接收时保持不变，不启动下一次读取。忙碌时不会接收新的请求；调用者必须等ready，不能发送无握手的一拍脉冲后假定已接收。
- [hall_scan_store.sv](src/hall_scan_store.sv)：每个键保存最新12bit原始电压读数、是否读到过、更新脉冲、更新时间和距上次有效更新的时钟数。异常通道保留上一次值，继续计时。
- [hall_adc_scan.sv](src/hall_adc_scan.sv)：将读取器和存储器连接起来，按固定节奏扫描。`enable=0`时完成已开始的读取，然后停下；恢复后从下一个通道继续。复位则清空数据并从0开始。

数据排列：`key_values[12*k +: 12]`属于键k；ADC0的CH0～CH7对应键0～7，ADC1的CH0～CH7对应键8～15。`CHANNELS`可设1～8，第二块的偏移随之变为CHANNELS。两块ADC的DOUT不能短接，即使共用片选。

## 默认速度与配置

默认50MHz系统时钟、SPI目标1MHz、每键目标2000次/秒。每次读取一对通道的开始间隔为3125个系统时钟，完整16键更新一轮500微秒；不是16键在同一瞬间取样。ADC0/ADC1同一对通道同时采集，各通道间存在时间差。

`CLK_HZ`必须填写模块实际输入时钟频率，不能沿用默认值却接12.288MHz。SPI半周期向上取整，因此非整除时实际SPI速度略低于目标。扫描间隔同样向上取整，实际每键速率不会高于目标。`KEY_RATE_HZ`设置过高、无法容纳一帧时，仿真会明确报错，不悄悄降低速度。默认1MHz是保守低电压配置，不支持在本轮直接将SPI设为2MHz。

主逻辑全部使用系统clk，SCLK只是输出脚波形，不拿它当内部派生时钟。DOUT经过两级同步，分频参数必须给ADC输出延迟及同步路径留出时间。需要稳定、低阻抗的模拟信号和参考电压；真实源阻抗、走线和磁轴行程影响只能待实物验证。

## 各个标志是什么意思

- `key_seen[k]`：这个键至少得到过一次通过格式检查的读数；复位后为0。
- `key_updated[k]`：这个系统时钟刚更新了该键，只有一拍；一对正常通道同时产生两个位置的更新。
- `key_stale[k]`：还没读过，或距上次有效更新超过允许时间。默认10ms；暂停扫描也会变旧。不要只看数值而忽略这个标志。
- `key_age_cycles`：距上次更新的系统时钟数，到STALE_CYCLES后饱和，不回绕。
- `key_timestamp`/`timestamp`：32bit系统时钟时间戳，按2^32自然回绕；用于比较时应做模减，不能当作不回绕绝对时间。50MHz下约85.9秒回绕一次。过期判定不依赖这个回绕的时间戳。
- `pair_error[1:0]`：对应ADC1/ADC0的固定null位不是0；有错误的那一路不更新键数据。`protocol_error_sticky`记录出现过的错误，复位清除。
- `scan_done`/`scan_count`：扫完一轮的脉冲/轮数，表示完成了读取尝试，不保证该轮所有通道都没有格式错误；应结合updated/stale/error判断。

**不能把这些标志当作可靠的ADC断线检测。** MCP3208没有ready/应答引脚；DOUT始终为0仍可能看起来像合法的0电压，始终为1能触发null错误但不是完整诊断。存储器的过期监测只检查有效更新是否停止，不检测传感器真实健康状态。硬件回来后可评估已知参考电压测试，但本轮不增加此功能。

## 测试入口

```powershell
./scripts/run_checks.ps1 -Suite adc
```

或使用当前Python执行`scripts/verify_adc.py`。独立模拟ADC在SPI引脚边沿解析指令、下降沿延迟输出数据，不读取发送器内部状态。覆盖不同主时钟/分频、通道数1/3/8、0/4095、位序、返回值反压、忙请求、异常null、暂停/恢复、计时饱和和中途复位；并执行严格Verilator和通用Yosys检查。输出位于`sim_out_adc/`，不使用历史音频回归结果替代本轮ADC证据。
