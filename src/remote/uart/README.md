# 通信协议

默认运行配置115200、8N1，时钟12.288MHz，均可参数化。这是本项目约定。ESP32与FPGA双方统一此参数。

每帧固定16字节，小端序。UART读取可以任意拆分，不能用一次串口读取当作帧边界；ESP32负责HTTP与本帧协议的转换。

| 字节 | 含义 |
|---|---|
| 0–1 | A5 5A |
| 2 | 版本01 |
| 3 | 序号0–255 |
| 4 | 命令号 |
| 5 | 有效载荷长度0–6 |
| 6–11 | 载荷，不用的字节必须填0 |
| 12–13 | 保留，必须为0 |
| 14–15 | CRC16低字节、高字节 |

CRC16/CCITT-FALSE：poly1021、initFFFF、refin/refout=false、xorout0000，覆盖字节2–13。标准向量123456789→29B1。CRC用于传输错误检测；Wi-Fi使用热点密码，CRC不是身份认证。

应答命令固定80，序号与请求相同，载荷长度6：`[原命令,状态,结果0,结果1,结果2,结果3]`。状态0成功/请求被接收，1参数或事务状态错误，2未支持命令，3忙/未在时间内接收，4相同序号内容冲突。坏CRC/格式的请求丢弃，不应答。

| 命令 | 载荷 | 功能 |
|---|---|---|
| 01 | 无 | 握手，返回32位42543031 |
| 02 | 无 | 查询状态，见下文 |
| 10 | 模式1字节：0/1/2 | 请求琴键/特雷门/合奏 |
| 11 | 音色1字节：0..4 | 请求钢琴/管风琴/长笛/吉他/钟琴 |
| 12 | 音量uint16 | 0..65535，65535为单位增益 |
| 13 | 效果1字节：0..31 | bit0音板、bit1混响、bit3:2 EQ、bit4限幅；最终适配须与现有效果接口一致 |
| 20 | 无 | 开始新键位表，清空完成标记 |
| 21 | 索引0..31、MIDI音符36..96 | 写1个暂存键位 |
| 22 | 无 | 收齐32项且tables_safe与keymap_safe为1才原子提交 |
| 23 | 无 | 放弃暂存键位表 |
| 30 | 曲谱长度1..32 | 开始新指引曲谱 |
| 31 | 索引、MIDI音符、力度、时长低/高字节 | 时长1..65535ms；力度0表示休止 |
| 32 | 无 | 收齐全部曲谱项且tables_safe为1才原子提交 |
| 33 | 无 | 放弃暂存曲谱 |

02返回4字节：结果0 bit1:0实际模式、bit4:2实际琴键音色、bit5切换中、bit6故障、bit7保留；结果1是最近经cfg握手接收的效果；结果2–3是最近经cfg握手接收的音量。模式/音色来自外部真实状态输入；音量/效果是命令记录，外部本地按键若修改参数不会自动同步，不能把后两者称为实际测量值。

## 重试和节流

客户端必须停等：一个请求收到应答后才发下一个。超时重发完全相同的16字节，包括序号；收到明确错误后若再次尝试，使用新序号。FPGA只缓存最近一个请求/应答；重复相同请求重发缓存，不重复执行；相同序号不同内容返回4，不覆盖缓存。支持255→0，但不提供跨复位、跨并发客户端或任意历史请求的严格一次性保证。一个模块只使用一个控制客户端，不启用多连接同时写。

ESP32每次500ms，电脑默认1秒应答期限，均最多额外重试2次。所有重试都失败时，命令可能已执行，不自动假定失败；查询实际状态。FPGA收到配置请求后等cfg_ready最多200ms，超时撤销未接收请求并返回3。应答是在串口发送之后到手机，Wi-Fi及串口实际延迟需实测。

FPGA单字节间隔默认100ms、滑动窗口总期限1s；包解析保留1个待处理请求，控制器另有1个在途请求，响应串行化也有1帧存储，不是无上限FIFO。违反停等可能丢帧并增加dropped_packets。错误后下一完整帧恢复；持续噪声可能导致一个完整帧被总期限打断，客户端应按停等重试。

5秒无合法请求只将linked清零并放弃未提交下载；保持活动键位、曲谱和本地声部。linked是近期协议活动指示，不是Wi-Fi物理连接状态。控制器实际音频参数处理在主工程适配器中，不依赖手机心跳。

## PC先验证

从D:/fpga26运行：

```powershell
D:\anaconda\python.exe -B lanya/tongxin/serial_control.py --demo
D:\anaconda\python.exe -B lanya/tongxin/serial_control.py --list
# COM号和波特率按实物确认，不要直接照抄：
D:\anaconda\python.exe -B lanya/tongxin/serial_control.py --port COM5 --baud 115200 --mode 2
```

--demo仅展示编解码，不需硬件。--port需要pyserial及已接入本协议的FPGA或测试端；需要连接运行本协议的FPGA；ESP32提供的网页接口另见esp32/README.md。该工具不烧录。

握手常量42543031沿用原协议，只是版本标识，不代表必须使用蓝牙。ESP32遇到明确的序号冲突会换新序号再试一次；不把未确认的超时当成功。

## 本轮扩展命令

| 命令 | 请求 | 应答结果4字节 |
|---|---|---|
| 03 | 无 | 实际已应用volume低/高、BPM低/高 |
| 04 | 无 | 活动曲谱事件数、playing(0/1)、提交版本低/高 |
| 14 | BPM uint16，30..240 | cfg接收ACK，之后用03核实 |
| 15 | 播放标志uint8，0停止1开始 | cfg接收ACK，之后用04核实 |

12音量请求继续使用0..65535，但手机不再用02的历史命令记录证明音量生效，改用03读取真实wifi_volume增益。31的时长字段现在解释为120 BPM基准毫秒；默认BPM120时与旧毫秒曲谱一致，四分音符500，播放器按BPM缩放。提交版本为uint16，可回绕。32提交成功后版本加1，手机核对原版本+1和事件数量；失败、未收齐或播放中提交不改变活动表。HTTPS下载文件与UART事务是两步，预览不等于提交。

## 32键扩展（两块琴各16键）

帧长度、CRC和停等策略不变。20开启暂存事务，21逐项写0..31，22只有32项完整且安全条件满足才原子替换；23放弃。未完成、超时、拒绝提交均保留旧活动表。重复相同序号/内容不会重复提交或增加版本。

| 命令 | 请求载荷 | 应答结果4字节 |
|---|---|---|
| 05 | 无 | 总键数32、保留0、映射版本低/高 |
| 24 | 键索引0..31 | 索引、实际MIDI音符、映射版本低/高 |

映射版本uint16，复位0，成功提交加1；读取只读活动表，不读暂存表。ESP32先读取05确认32键能力，再读取24的32项；每项版本须一致。提交后要求版本=旧版本+1并且32项逐一相等，否则不报成功。协议不提供跨FPGA复位事务保证，失败时重新读取实际映射。单客户端停等，禁止并行改表。
